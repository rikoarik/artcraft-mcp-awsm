# Design-only deliverable in FigCraft

A design request ends in the native design document. Inspect the intended open
file/page, preserve current work and use craft_prepare with its resolved briefId.
Build only the requested frames, live text, layout, assets and component/state
variants. A new variation may belong on a new page/frame in the same document;
it does not authorize replacing or exporting the whole file.

Use the matching screen blueprint and existing component styles. Add only the
state sheet needed to explain the flow. If motion is part of the design, represent
its trigger, transition, reading hold and end state using supported native prototype
features or clear annotations. A static annotation is not a running web animation.
Do not install web dependencies, start a dev server, generate routes, export a
website or call design_quickstart for this output.

Inspect the actual native frame render and layer structure. Verify alignment,
font/crop, contrast, editable controls, component variants and required navigation
intent. Provide the native document location, relevant frame IDs, inspected views
and limitations. Browser DOM audits are not a substitute for native canvas checks.

If the user subsequently asks to make a website from this design, resolve/update
the brief to website output and use from-figcraft handoff. Inspect the actual source,
map editable UI to code, export independent artwork and implement the requested
website. The presence of a FigCraft document alone does not imply this request.
